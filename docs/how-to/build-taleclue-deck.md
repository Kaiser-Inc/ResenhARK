# Build the Taleclue deck

Taleclue plays with 120 illustrated cards: four batches of 30, one style, no repeated image. The illustrations are generated by hand in the Gemini app, so this page covers the loop around that: prompts out, images in, optimized cards and a manifest back.

You need Node 22 and pnpm. Nothing here calls an API, and no test needs the images.

## 1. Know the files

| File | What it is |
|---|---|
| `apps/web/scripts/taleclue-deck/concepts.json` | The 120 concepts: opaque `id`, `batch`, `scene`, `palette`, pt-BR `alt`, `people` |
| `apps/web/scripts/taleclue-deck/style-guide.md` | The style rules and the exact text of the fixed Gemini instruction |
| `apps/web/scripts/taleclue-deck/prompts/lote-N.md` | One ready-to-paste prompt per concept, generated from `concepts.json` |
| `.taleclue-raw/` | Your raw images, outside git |
| `apps/web/public/taleclue/cards/` | Output: `<id>.webp` (800×1200) and `<id>.thumb.webp` (400×600) |
| `packages/shared/src/taleclue-deck.json` | Output: `{ id, alt, batch }` for each approved card that has an image |
| `apps/web/scripts/taleclue-deck/provenance.json` | Output: prompt, batch, model, date and `approved` per card |

## 2. Set up Gemini once

In the Gemini app, create a Gem named "Cartas" and paste the fixed instruction from `style-guide.md`. Do not edit it while you produce the batches, because the style would drift without a trace. Every prompt then is only the scene, the palette and `No people.`.

## 3. Generate a batch

1. Open `prompts/lote-N.md`.
2. In a chat with `@cartas` and the image model, paste one block. Gemini returns variations.
3. Pick the best one and save it as `.taleclue-raw/<id>.png` (`.jpg` and `.webp` also work). The id is in the heading of the block.

Keep the image 2:3. Gemini returns about 848×1264 or 1696×2528; both pass. Cards made before this naming (or downloaded as `cardN.jpg`) are linked by the optional `rawFile` field of the concept, for example `"rawFile": "pilot/card8"`. The script tries `<id>` first and then `rawFile`, so they need no renaming.

To redo a bad card, edit its `scene` or `palette` in `concepts.json`, regenerate the prompts and generate it again:

```sh
pnpm --filter web exec tsx scripts/taleclue-deck/gen-prompts.ts
```

## 4. Convert

```sh
pnpm --filter web exec tsx scripts/taleclue-deck/build.ts
```

The script is safe to run any number of times, with any number of images. For each image it:

1. rejects it when the ratio is not 2:3 (±2%) or the size is under 800×1200, and exits with an error at the end;
2. crops the center to exact 2:3 (at most 2% is lost) and writes the card and the thumbnail as webp;
3. warns about a possible visible mark in the bottom-right corner and about a flat border or frame.

Then it rewrites the manifest and `provenance.json`, and prints how many cards each batch has and which ids still have no image.

The two warnings are heuristics, not detection: the first compares how busy the bottom-right corner is against the other three, the second looks for a uniform edge strip. Neither reads text. Look at every card before you approve it.

## 5. Approve and remove

A card is `approved: true` when it is first built, because you already picked the best variation. To pull one from the deck, set `approved` to `false` in `provenance.json`; the script keeps your value on later runs and leaves that card out of the manifest. `date` and `model` also stay as first written. Pass `--model "name"` to record another model for new cards.

## 6. Check and commit

```sh
pnpm --filter web test
```

The test in `scripts/taleclue-deck/deck.test.ts` checks the concepts (120, 30 per batch, unique ids and scenes) and the size rules. Commit `concepts.json`, the prompts, the cards, the manifest and the provenance together. The raw images stay out of git.
